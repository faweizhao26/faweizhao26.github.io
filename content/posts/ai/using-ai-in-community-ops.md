[上一篇文章](https://faweizhao26.github.io/posts/ai/codex-ai-website/)里，我写了自己用 AI 做了一个导航网站的经历，应该有一些朋友已经看过了。

AI 早就不是新鲜事了，它已经悄然"侵入"了我们的生活、工作和学习，成为很多人离不开的一部分。作为一名社区小运营，AI 更是成了我的得力助手。这篇文章，主要就是想聊聊最近我用 AI 都干了些什么，希望能给大家带来一点启发。

## 一、在工作里，我用 AI 干了这些活儿

认识我或者关注我有一阵子的朋友应该都知道，我的本职工作是社区运营。之前也写过一些关于运营经验、方法与工具的文章。

那么，我最近到底怎么在工作中使用 AI 的呢？

像用 AI 辅助做方案策划、生成图片这些，估计大多数人都已经在做了，我就不多说了。重点讲讲几个可能有些小伙伴还没尝试过的用法。

### 1. 搞定网站前端设计

我现在运营的是一个开源数据库项目，叫 **IvorySQL**。接手之后，我就一直觉得官网有点过于简单，脑海里翻来覆去想过无数次优化的念头。但无奈自己既不懂设计也不会前端，实在是两眼一摸黑。

去年 12 月，我白嫖了一年的 Gemini 会员，开始重度使用它。听闻 Gemini 很擅长前端设计，我就想，何不让它来帮我设计官网的某些页面。

于是，在 Gemini 的帮助下，我先做出了几个新页面：[活动页面](https://www.ivorysql.org/zh-cn/events)、[合作伙伴页面](https://www.ivorysql.org/zh-cn/partners-page)和[社区动态页面](https://www.ivorysql.org/zh-cn/news)。虽然用了 AI 工具，但自己投入的时间和精力一点不少。当然，这中间还有个前提：我提前请公司的设计师帮忙出了一个大概的前端 UI，把设计稿喂给 Gemini，才在这个基础上做出来的。

后来，我又动了重构官网[首页](https://www.ivorysql.org/zh-cn/)的念头。这时我已经开始用 Codex 了，它让事情变得更简单——我只需要动动嘴指挥，不用自己编辑文件，甚至不用亲自提交 PR，人力成本大大降低。不过目前这个首页，是同事在我 PR 的基础上，又用 Claude Code 二次加工过的。

后面因为忙起来，几个页面的 UI 就没再继续打磨了，但已经比最初的版本好了很多。

### 2. 给自己做点实用小工具

我平时也爱推荐一些小工具，比如 PDF 编辑、图片处理、格式转换之类的。工作中总会碰到各种零碎的需求：格式转换、图片裁切、照片排版……以前我的方法是：先从自己的收藏夹里找，没有就上网上搜，但网上很多工具最后都要付费。

Gemini 除了文字对话、生图，其实还能写小应用。所以我就用它做了一些在线小工具，比如把 SVG 格式的图片转成 PNG 或 JPG、把 PPT 页面转成图片、图片裁切等等。这些应用都放在 Gemini 里，只限我自己使用，方便又省钱。

### 3. 搭建数据看板

很多岗位都有数据指标，社区运营当然也不例外：开源项目的 Star 数、官网的 UV/PV、公众号的关注数和文章阅读量、贡献者数量……等等。

我们需要定期关注这些数据的变化，就免不了反复做统计。说实话，数据统计一直都是我最头疼的事情。指标太多，东一个西一个，需要你不断统计、汇到一起，再做变化分析，麻烦得很。

前一阵子我就琢磨：能不能做一个数据看板，把我需要关注的数据全整到一起，一目了然，还能省下大把时间和精力。于是，我先后用 **Codex** 和 **opencode** 开始动手做这个看板。之所以用了两个 AI agent，是因为我买的中转站 token 到期了，后面换的 minimax 和 DeepSeek token 都无法在 Codex 的 Mac 桌面端使用，所以现在是暂时被迫停了 Codex。

最终，我做出这个半成品：https://ivorysql-dashboard.vercel.app/

说它是半成品，是因为有些数据的统计逻辑还没完全搞对，有些数据的通道还没打通，还有一部分数据需要我手动录入。

简单说一下实现逻辑：在 GitHub 上新建仓库，把网站代码写完，然后部署在 Vercel 上，再链接 Supabase 作为后端数据库。全程没使用任何付费功能。

所以，如果你想复刻一个，直接 fork 我的仓库就行：https://github.com/faweizhao26/ivorysql-dashboard

这是一个基于 Next.js 的开源项目运营数据看板，支持 GitHub 数据自动获取和手动录入。

**功能特性：**

- **GitHub 数据**：Stars、Forks、Watchers、Contributors、Open Issues/PRs、Release 等
- **社交媒体**：公众号、Twitter、B 站、YouTube 的粉丝和互动数据
- **技术内容平台**：CSDN、掘金、墨天轮、开源中国、思否、51CTO、ITPUB、头条号、IFCLUB
- **官网数据**：PV/UV、流量来源、热门页面、搜索关键词
- **趋势图表**：支持日/周/月/季/年维度切换
- **社区动态**：聚合 GitHub Issue/PR/Release、博客更新、活动动态
- **自动更新**：通过 GitHub Actions 每日自动抓取
- **权限控制**：Vercel Password Protection 密码保护

每个项目的运营重点不同，我现在做的这个看板也只是贴合自己当下的需求，后续我会持续更新。如果你有好的思路，也欢迎来找我交流。

### 4. 造一个大会（活动）官网

入职瀚高一年多，我已经组织了两场大会：去年的 HOW 2025，和今年的 HOW 2026。

经历过这两次大会的组织痛点后，我心里冒出一个想法：干脆用 AI Vibe Coding 把 HOW 2027 的官网给撸出来。这个官网不仅要承载一些重要信息展示，还要能提交议题、编排议程，更要有注册报名和现场签到功能。这样我就不再需要为议程管理系统、活动管理系统付费了，拥有一个功能大而全的官网。

实现思路跟上面的看板网站一样。目前这个也还是半成品，依然在持续打磨优化中。

开源仓库在这里，有需要的尽管拿去用：https://github.com/faweizhao26/HOW-WEBSITE

考虑到数据安全与隐私问题，如果后续真要投入使用，后端数据库就不能继续用 Supabase 了（目前用的是 Supabase 云端）。好在瀚高正在做一个 Supabase 中国版的替代产品，等出来后我就换掉。

### 3. "养龙虾"

前阵子国内掀起了一股"养龙虾"的热潮。当然，这不是真养虾，而是一个非常火的 AI agent 项目，叫 **openclaw**。项目 logo 是只龙虾，所以大家就管它叫"龙虾"了。这股热潮还催生了国内的"百虾大战"，多家公司下场，做出了自己的龙虾智能体。

我这人一向爱追热点，第一时间就部署了 openclaw，按照网上的教程，把它和飞书打通了。不过一开始，并没找到特别合适的应用场景。

秉持着"没有需求就创造需求"的原则，我后来还是给它找了些活儿干：

**（1）搞公众号**

我去年新注册了一个公众号，本来也没想好写什么，几乎等于没运营起来。后来灵机一动：既然 AI 这么火，干脆让 AI 来写 AI。为了防止被监测到封号，具体写的什么方向、公众号叫什么名字，这里就不透露了，只给大家提供一个思路。

经过多轮迭代优化后，现在的流程是：每天 openclaw 跑定时任务，用 DeepSeek 生成文章，然后通过飞书和本地 Markdown 文件把内容推给我，我再去做最后的排版和发布。

**（2）推送 AI 新闻**

我一直很关注 AI 的动态和新闻，AI 方向的公众号关注了一大堆。后来就想，为什么不让 openclaw 帮我梳理和推送 AI 新闻呢？正好这两天 AI 大 V「数字生命卡兹克」开放了自己的 AI 热点监控网站，并做成了 skill。我也很快让 openclaw 装上了这个 skill，优化了新闻推送的质量。

### 4. 尝试写小说

说实话，这块我本来不太想提。用 AI 写小说，目前体验下来还是不太行，也可能是我用的工具还不够好。至今没什么成果，就权当提供一个思路吧。

## 三、简单总结一下

上面这些，就是我近期用 AI 在折腾的事情。

**先说说我现在常用的几个 AI 和它们的用途：**

- **Gemini**：现在已经用得比较少了，我公众号的封面会用 Lovart（底层调的是 Gemini）生成。
- **ChatGPT**：现在主要拿来生图，效果真的很顶。
- **DeepSeek**：用来生成内容，以及使用它家的 token。
- **openclaw**：作用上面写过了，不再重复。
- **opencode**：做我需要的各种网站。

**再说下我用过的 token：**

- **中转站**：确实好用，但不稳定，而且相对较贵。
- **minimax**：真的不太好用，可能因为我买的套餐太便宜。
- **DeepSeek-v4**：百万上下文真的很顶，而且按用量计费，不算贵。

上一篇文章里我就说过，AI 拉低了某些事情的门槛，让我们能做到很多从前只能想想、做不了的事。接下来，我还会继续用 AI 去做一些需要的东西，也随时欢迎大家来一起交流。
